4. 검증 범위와 남은 항목

CSV는 헤더 없는 MySQL OUTFILE 형식이다. NULL과 빈 문자열을 구분하고 역슬래시 이스케이프를 해석했다. 줄 수가 아닌 CSV 레코드 수를 사용했고 금액과 시간은 Decimal로 계산해 소수 오차를 피했다.

  • DB에 직접 접속해 전체 원본과 바이트 단위로 대조한 검증은 아님
  • 격리·제외 원본 텍스트는 현재 ZIP 안에서 형식과 보존 컬럼을 검사했으며 최초 Bronze 파일과 전수 대조하지 않음
  • 현재 마스터의 Y 판정을 원본으로 재검증하지 않음. 원본 ACTIVE_YN 전체가 이번 ZIP에 포함되지 않음
  • 예측 평가 실제값을 이전 실행 화면의 합계와 대조하지만 이번 ZIP에는 원천 검사 단계 전체가 없음

파일 내부의 구조·관계·계산 정합성과 이전 DB 실행 결과의 주요 기준값을 확인한 검증이다. 최초 Bronze 파일과 모든 문자열을 바이트 단위로 대조한 전수 검증을 뜻하지 않는다.

기존 품질 기록은 PASS 14개, NOT_CHECKED 1개, RECORDED_DIFFERENCE 1개를 유지한다. 점검 구간 미검증과 상대팀 기준 건수 차이는 해결된 것으로 바꾸지 않았다. 예측은 한 주 평가, 인력은 실제 근무 가능 시간이 아닌 가정 시나리오라는 한계도 유지한다.
